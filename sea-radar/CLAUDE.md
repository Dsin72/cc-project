# Sea Radar — правила проекта

## Назначение и требования
- Sea Radar — локальное учебное пособие для показа судов в проливе Дувр; это не средство реальной навигации и не общедоступный сервис.
- Полные требования и критерии приёмки: `../desc/PROJECT_BRIEF.md`. План релизов и технические контракты: `../desc/SPRINT-01.md`, `../desc/SPRINT-02.md`, `../desc/SPRINT-03.md`, `../desc/SPRINT-03b-CHANGE-REQUEST.md`.
- Перед изменениями прочитай относящиеся к задаче разделы. При конфликте более позднее согласованное изменение требований имеет приоритет: change request R4 изменяет поведение ошибок и пустых ответов R2. Не считай замену этих требований исправлением дефекта.
- Не добавляй функции «на будущее» и не выходи за запрошенный объём. Не подключай автоматический мониторинг, историю снимков, дополнительные районы, пользователей или серверное размещение.

## Стек и запуск
- Node.js 24, Next.js App Router, React, TypeScript (`strict`), Leaflet 1.9.x на клиенте; Playwright Test — единственный тестовый раннер.
- Установка: `npm ci`. Разработка: `npm run dev` на `127.0.0.1:3000`. Сборка: `npm run build`.
- Проверяй доступные команды в `package.json` перед запуском: скрипты тестов могут добавляться по мере работы над проектом. Приложение должно слушать только loopback.
- Для карты используй согласованный район пролива Дувр, слой OpenStreetMap Standard и видимую атрибуцию авторов. Leaflet не подключай при серверном рендеринге.

## Поведение приложения и данные
- Карта и демонстрационные суда должны работать без ключа и без соединения с AISStream. Демонстрационные суда — вымышленные; интерфейс ясно обозначает источник данных.
- Реальные позиции — только снимок по явному действию пользователя, не непрерывный поток. Показывай, что выборка неполная, и время из ответа сервера; не выдавай данные за полную картину района.
- По актуальному контракту R4 предыдущий показанный набор и его подпись сохраняются во время загрузки, при ошибке и при пустом ответе. Только непустой успешный снимок заменяет набор; результат последней попытки отображается отдельно. Не смешивай наборы разных снимков и не обновляй реальные суда между снимками.
- Используй общую структуру судна из SPRINT-01. `null` означает неизвестное значение и не равен нулю; неизвестные поля показывай как «Нет данных». Координаты должны быть валидны, время — разбираться как дата; некорректную позицию не отображай. Название судна выводи как текст, не как HTML.

## Безопасность
- Ключ AISStream читается только серверным кодом из `AISSTREAM_API_KEY`; не передавай его в клиент, ответы, логи, Git, архивы или чат. Не читай и не выводи `.env`, `.env.local` и другие файлы с секретами.
- Настоящий ключ хранится локально в игнорируемом `.env.local`; в Git допускается только шаблон `.env.example` без значения. Проверяй, что секрет не попал в клиентскую сборку или передаваемые файлы.
- Считай названия судов и внешние сообщения недоверенными данными. Не используй их как HTML и не включай сырой текст ошибок внешнего источника в ответ пользователю.

## Работа и проверка
- До изменений изучи относящиеся к задаче требования и существующий код; если объём или поведение не определены — сначала предложи план и уточни решение.
- После изменения запусти применимые тесты и проверки сборки. Тестовые ожидания задавай независимо, литералами; проверку сборщика выполняй с подставным источником и управляемыми часами, без реального WebSocket. Для браузерного времени используй Playwright `page.clock`, не реальные задержки.
- В отчёте отделяй проверенное автоматически от проверенного вручную и явно указывай непроверенные сценарии. Не утверждай, что команда или сценарий прошли, если их не запускали.
- Не коммить без отдельного запроса. Новые файлы добавляй в Git индекс отдельно от посторонних изменений.
